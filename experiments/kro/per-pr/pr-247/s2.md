# S2: partition match (PR #247)

## Input partition

- Reconcile event: spec change vs no spec change.
- SSA target: existing object owned by us vs not vs absent.
- Revision transition: with prior revision vs without.
- Watch event vs resync timer (the latter not exposed if optimization layer is gone).
- Prune candidate: passes preflight vs fails.
- forEach state: carry-forward applicable vs not.

## Branching partition (pre)

- Apply path branches on cache hit / miss / apply-hash match.
- Graph compilation branches on content-addressed share lookup.
- Revision compile branches in 6 places.
- Event router branches over 6 shapes.
- Apply does prepare + ownership + patch + eviction + classification in one block (sub-cells implicit).
- Prune and delete have separate preflight cells.
- forEach carry-forward state lives in cells across function boundaries.

## Branching partition (post)

- Apply path is sequential through `prepareObject`, `checkOwnership`, `ssaPatch`, `evictThirdPartyManagers`.
- Revision compile branches in 2 places.
- Event router has one concern.
- Prune and delete share preflight cell.
- forEach carry-forward is one struct cell.

## Cells in pre's branching partition not in post's

- **Cache hit / miss / apply-hash cells.** Classification: **(a) relocated to a richer cost function** (deferred to API server's field-manager apply-hash; design holding pen `007-optimizations.md`). Input case is no longer in the partition the preferences require.
- **Content-addressed share lookup cell.** Classification: **(b) deleted**. Input case (cross-instance sharing) is not in the preferences-rewarded partition.
- **Six compileRevision branches.** Classification: **(a) relocated**. Reduced to 2 at the top; other cells live in helpers.
- **Six RouteEvent cases.** Classification: **(a) relocated**. One top-level concern; cases handled where they arise.
- **Five-concern monolith inside applySSA.** Classification: **(a) relocated to module structure**. Each concern is its own named procedure.
- **Duplicated preflight cells.** Classification: **(a) relocated**. Shared via `deletePreflight()`.
- **forEach carry-forward field cells.** Classification: **(a) relocated to types**.

## Cells in post's branching partition not in pre's

- **Decomposed apply cells.** Classification: **(a) preferences require this distinction** (each step has different failure modes; pre's monolith hid them).
- **forEachCarryForward struct cell.** Classification: **(a) preferences require** (type-level bundling makes the shape inspectable).

## Verdict

**S2 improved.** Pre's branching partition was finer-than-required along several axes (cache, sharing, monolithic apply, six-way dispatch). Post collapses these and surfaces the cells the preferences actually need (named apply steps, struct-level carry-forward).

Citation: seven over-fine cells collapsed via (a)/(b); two preference-required cells added.
