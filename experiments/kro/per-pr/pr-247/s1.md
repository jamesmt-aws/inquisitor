# S1: deletion-minimality (PR #247)

## Procedures and properties in design-pre absent from design-post

- **resourceCache lookup and elision** (P1, related architecture). Classification: **(a) deleted**. Input case: cache hit on unchanged nodes. The preferences (correctness, observable behavior, public API stability) do not require this distinction at the controller layer; the design holding pen `007-optimizations.md` defers it. Deletion loses no preference value.
- **Content-addressed graph sharing** (P2). Classification: **(a) deleted**. Input case: structurally identical graphs sharing storage. Deferred by design; not required by preferences.
- **forEach child precompile**. Classification: **(a) deleted**. Same reasoning.
- **Revision diff and carry-forward** (P3). Classification: **(a) deleted**. Same reasoning. Correctness is preserved by full re-evaluation across revision transitions.
- **Revision Ready and Active conditions** (P4). Classification: **(a) deleted**. Input case: external observers learning revision lifecycle from CRD status. Preferences include observable behavior, but the team's labeled intent is that GC-only conditions are sufficient surface; this is a deliberate API contraction. Borderline (a)/(c).
- **Watch interfaces** `DrainTriggers` etc (P5). Classification: **(a) deleted**. Input case: alternative watch implementations consuming the interface contract. No production consumer; preferences do not require.
- **Resync-timer and self-refresh metrics** (P6). Classification: **(a) deleted**. Input case: operators observing these counters. Dead surface; deletion loses no preference value.
- **applySSA as one block** (P7). Classification: **(c) relocated to module structure**. The job is now four named procedures; case analysis is at the call site rather than inside a single function.
- **compileRevision with 6 branches** (P8). Classification: **(c) relocated**. Reduced to 2 branches at the top level; other distinctions absorbed into helpers.
- **RouteEvent with 6 cases** (P9). Classification: **(c) relocated**. Consolidated to one concern; case analysis moved into helpers where each case is local.
- **Duplicated prune/delete preflight** (P10). Classification: **(b) absorbed**. Shared `deletePreflight()` consumed by both paths.
- **forEach carry-forward as separate fields** (P11). Classification: **(c) relocated to types**. Bundled into a struct; the shape is encoded at the type level.

## Procedures and properties in design-post absent from design-pre

- **Decomposed apply procedures** (P7 post). Classification: **post (a)**. Preferences require legible apply behavior; pre's monolith had the case analysis hidden inside one function body.
- **forEachCarryForward struct** (P11 post). Classification: **post (a)**. Type-level bundling encodes a constraint that pre held implicitly across function signatures.

## Verdict

**S1 improved.** Every (a) deletion targets an input case the design holding pen (`007-optimizations.md`) defers, or a dead surface with no consumer. Every other removal is (b)/(c). Two post additions are post-(a) covering input cases the preferences require. No introduced complexity that the preferences do not reward.

Citation: deletions split (a) optimization-layer + dead surface, (b) prune/delete preflight, (c) apply/compile/route/forEach decomposition; post additions encode constraints at structure level.
