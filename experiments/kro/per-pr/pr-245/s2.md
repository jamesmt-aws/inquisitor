# S2: partition match (PR #245)

## Input partition

- Reconcile reason: spec change vs watch event vs resync. (Preferences require correctness across all three.)
- Node: needs evaluation vs already up-to-date. (Preferences do not distinguish; correctness only requires that the result is correct, not that the work was minimized.)
- Apply target: identical to last apply vs different. (Preferences require no unnecessary API writes; this is the only optimization-related cell preferences require.)
- forEach item: present vs absent vs changed-since-last.
- Watch event: spec-affecting vs not.

## Branching partition (pre)

- Reconcile reason cells: Path 1 (stale-read self-refresh), Path 2 (watch-driven), Path 3 (resync-driven). The coordinator branches on the source.
- Node-level skip cells: input-hash match / mismatch; self-hash match / mismatch; field-path hash match / mismatch.
- Subgraph routing cells: trigger-scoped walks for watch events.
- Worker dispatch cells: ready / blocked / completed.
- forEach skip cells: item content hash match / mismatch.
- Watch cache cells: dirty / clean.
- Apply cell: SSA Patch hash match / mismatch.

## Branching partition (post)

- Reconcile cell: one (sequential loop runs end to end).
- Node-level cell: one (every node evaluated).
- Subgraph cell: collapsed (full walk).
- Worker cell: collapsed (no workers).
- forEach cell: one (every item evaluated; gate halts via propagateWhen).
- Watch cache cell: collapsed (informer state used fresh each reconcile).
- Apply cell: SSA Patch hash match / mismatch (preserved).

## Cells in pre's branching partition not in post's

- **Path 1/2/3 distinction.** Classification: **(b) deleted**. The input case (reconcile reason) does not need to be distinguished at this layer; correctness holds across all three with one loop.
- **Multi-layer hash skip cells.** Classification: **(a) relocated to a richer cost function** (deferred to apply-layer SSA hash). The input case (avoid unnecessary API writes) is still handled, just at a different layer.
- **Trigger-scoped subgraph cells.** Classification: **(b) deleted**. Input case (partial walk) not in the preference-rewarded partition.
- **Worker dispatch cells.** Classification: **(b) deleted**. Input case (parallel evaluation) not preference-required at this resolution.
- **forEach per-item skip cells.** Classification: **(b) deleted**. Input case (per-item skip) not preference-required.
- **Watch cache dirty/clean cells.** Classification: **(b) deleted**. Input case (incremental cache merging) not preference-required.

## Cells in post's branching partition not in pre's

- **Single-loop cell.** Classification: **(a) preferences require legibility**. Pre's branching partition was finer than the preferences rewarded; post collapses the over-fine cells into one loop that the preferences directly address.
- **Apply-layer hash cell preserved.** This is unchanged; it is the only optimization-related cell preferences actually require, and it stays in both pre and post at the same place.

## Verdict

**S2 improved.** Pre's branching partition was finer-than-required along seven axes (Path routing, three hash layers, subgraph routing, worker dispatch, forEach skip, watch cache). Post collapses every over-fine cell. The one optimization cell preferences require (apply-layer SSA hash) is preserved in both. The collapse is a clean partition-match move toward the preference-required input partition.

Citation: seven pre cells collapse via (a)/(b) deletion or relocation; one cell preserved across the change.
