# S3: MDL compression (PR #249)

## Byte counts

| | design (md) | code (touched files) |
|---|---:|---:|
| pre | ~3500 | 536379 |
| post | ~3000 | 481431 |

Code shrank ~55K bytes (-10%). Design shrank because the pre-state architecture had to document the monolithic receiver, the four-parameter threading, the duplicated teardown/prune, and the optimization residue. Post-state design states the split structure briefly.

## Predictability of code given design

**Pre.** Score: 2 / 5. The architecture description in pre would say "GraphReconciler does both orchestration and execution; some methods need cluster access, some don't, but the type signature does not encode this." A regenerator following pre-design would put everything on one receiver and produce roughly what's there. The conditional cost is high because the design does not pin down which methods belong on which logical concern.

**Post.** Score: 5 / 5. Post-design names two receivers explicitly. A regenerator producing 10 orchestration methods and 15 execution methods on two types arrives close to the actual layout. `reconcileScope` and `pruneResources` are similarly load-bearing: a regenerator with the post-design produces the same shape as the post-code.

## MDL comparison

The MDL move here is stronger than #253 and roughly comparable to #245 for a different reason. #245 reduced description length by removing the optimization layer entirely; #249 reduces it by *naming* the structural commitments (clusterAccess, reconcileScope, pruneResources) so the design carries less prose and the code carries less repetition.

Net structural absorption: -1332 lines of code, ~ -500 bytes of design, predictability 2 → 5. The post-state's named-types-as-design-commitments pattern is the prototype for "push constraints into the structure of the thing."

## Verdict

**S3 improved.** Code shrank 10%; design shrank in proportion; predictability rose from 2 to 5. New structure (clusterAccess, reconcileScope, pruneResources, evalConditions, defaultNamespace, ssaWrite) earns its keep against the duplicated parameter threading, the monolithic receiver, the duplicated teardown, the scattered helpers it replaces.

Citation: -10% code bytes, design shrinks proportionally, predictability rises sharply because named types replace implicit conventions.
