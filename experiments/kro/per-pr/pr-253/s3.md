# S3: MDL compression (PR #253)

## Byte counts

| | design (md) | code (touched files) |
|---|---:|---:|
| pre | ~3500 | 537103 |
| post | ~3000 | 500301 |

Code shrank ~37K bytes (-7%). Design shrank because pre-state required documenting the dead surfaces and single-impl interfaces; post-state does not.

## Predictability of code given design

**Pre.** Score: 3 / 5. The architecture is mostly correct, but a regenerator following pre-design would produce code with several fields whose lifecycle the design does not explain (the dead ones), several interfaces whose second implementation the design does not name (the single-impl ones), and several extractor functions whose differences the design does not pin down (the per-condition ones). Conditional cost is moderate.

**Post.** Score: 4 / 5. A regenerator produces code that matches the design at every field, every interface, every extractor. The remaining unpredictability is at the level of test infrastructure and parser detail.

## MDL comparison

`|design| + cost(code | design)` shrinks on both axes. The design absorbs no new structure; what shrinks is the implementation surface that pre held without design backing. The MDL move here is "remove things that the design does not specify and the production does not consume" — both ends of the description benefit.

Net: -1000 lines code, ~ -500 bytes design, predictability 3 → 4.

## Verdict

**S3 improved.** Code shrank moderately; design shrank in proportion; predictability rose. New structure (shared helpers like `walkAST`, `conditionField`, `ensureFinalizerResource`) earns its keep against the duplicated implementations they absorb.

Citation: -7% code bytes, design shrinks; conditional cost drops as dead fields, parallel walkers, and single-impl interfaces leave the surface area.
