# S1: deletion-minimality (PR #248)

## Procedures and properties in design-pre absent from design-post

- None deleted. The runtime parser still runs every check it ran pre-state for cases the schema cannot express (duplicate IDs, mutual exclusivity, per-keyword shape). The polling-for-condition test pattern is replaced for some test cases (the schema-enforceable ones) but persists for others.

## Procedures and properties in design-post absent from design-pre

- **Apiserver-time admission rejection.** Classification: **post (a)**. Preferences (correctness, public API stability) reward catching malformed Graphs before they reach the controller. Pre-state had this as a missing input case at the API boundary.
- **Two distinct error surfaces.** Classification: **post (b)** with caveat. The change introduces a distinction (which errors surface where) that is finer than the input partition strictly requires; from a user's perspective, "Graph is invalid" is one input case, and the design now surfaces it through two channels. Borderline: the preferences arguably reward fast-fail at admission (post-(a)), but the resulting two-channel surfacing is also a complexity tax users absorb.

## Verdict

**S1 unchanged.** No removable units in pre-state lost. One post-(a) addition (admission validation). One borderline post addition (two-channel error surfacing). The change is not a deletion-minimality move; it is a feature add that fills a missing input cell at the API boundary while introducing a small surface complication.

S1 does not score "the input partition was extended in a useful direction"; it scores removability. By that scope, the change does not move S1.

Citation: zero (a)/(b)/(c)/(d) removals; one post-(a) addition with a post-(b) caveat.
