# S3: MDL compression (PR #248)

(Approximate; touched-file scope is small. CRD YAML grew by ~280 lines for graphs + ~150 for graphrevisions; test file shrank by ~180 lines as polling code dropped.)

Non-comment Go LOC: -17 (essentially flat).

## Predictability of code given design

**Pre.** Score: 3 / 5. Pre-design says "controller validates id format, required fields, condition types." A regenerator following pre-design would not produce a structural CRD schema; the design pins down validation at one layer.

**Post.** Score: 3 / 5. Post-design names two layers (schema + parser). A regenerator producing both arrives at the right shape. But the post-design is also longer because it has to enumerate which validation lives where. The conditional cost reduction at the schema layer is roughly offset by the new cost of describing the layer split.

## MDL comparison

`|design| + cost(code | design)` is approximately flat. The new schema absorbs constraints (id pattern, required fields) that pre's parser handled, but the parser still handles the residual cases, so the absorption is partial. Net description length is essentially unchanged.

The change is a feature add (admission-time validation) that costs roughly its own bytes and does not consolidate description length on either side.

## Verdict

**S3 unchanged.** Code grew (~10K bytes for CRD YAML); design grew correspondingly to describe the layer split; predictability flat at 3/5. New structure (the structural schema) earns its keep against partial absorption of parser checks, but does not produce a net MDL win.

Citation: bytes grow on both sides; layer-split description offsets schema absorption; conditional cost flat.
