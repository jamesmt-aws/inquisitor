# S2: partition match (PR #248)

## Input partition

- User submits valid Graph / invalid Graph (any field).
- Invalid by reason: missing id / invalid id pattern / wrong shape / duplicate id / mutual exclusivity violation / per-keyword shape violation.
- Operator inspects status to learn validation outcome / receives apiserver error directly.

## Branching partition (pre)

- Apiserver cell: accepts.
- Controller cell: validates, sets `Compiled: False` with `DeclarationError`.
- All invalid-Graph reasons collapse to one cell: "controller-time validation failure."

## Branching partition (post)

- Apiserver cell: rejects (schema-enforceable cases) or accepts (residual cases).
- Controller cell: validates only the residual cases (duplicate IDs, mutual exclusivity, per-keyword shape).
- Invalid-Graph reasons split: some at admission, some at controller.

## Cells in pre's branching partition not in post's

- None. Pre's "accept everything" cell is preserved as a subset of post's apiserver cell (residual cases still flow through).

## Cells in post's branching partition not in pre's

- **Admission-time rejection cell.** Classification: **(a) preferences require this distinction**. Public API stability and correctness reward fast-fail at the boundary; pre's branching partition was coarser-than-required because it folded all validation into the controller layer.
- **Two-channel error surfacing cell.** Classification: **(b) finer than input partition rewards**. From the user's input partition viewpoint, "Graph is invalid" is one cell; the design now distinguishes "invalid in a schema-enforceable way" from "invalid in a parser-only way." The preferences do not reward this distinction.

## Verdict

**S2 improved.** Pre's branching partition was missing the admission-time cell that the input partition required (correctness, public API stability both reward early rejection). Post adds it. The (b) caveat about two-channel surfacing is real but the (a) addition outweighs it under the stated preferences.

This is the predicted "feature add can score improved on S2 because it fills a missing input cell" case. Worth flagging in the aggregator: S2 says `improved` on a change the team did not label as a simplification.
