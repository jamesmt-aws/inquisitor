## Predictability of code given design

**Pre.** Score: 3 / 5. Pre-design says "applied keys are tracked across the walk." A regenerator could produce either a flat slice or a per-node map; design did not pin down the shape, and a flat slice would compile and look reasonable while harboring the bug.

**Post.** Score: 4 / 5. Post-design names the per-node map shape and the last-writer-wins invariant. A regenerator producing a flat slice now diverges from the design.

## MDL comparison

The bytes are essentially flat. The MDL move is in predictability: post's design pins down a shape that pre's left to implementer discretion. `|design| + cost(code | design)` is roughly flat, with the conditional cost slightly lower in post because the shape is fixed.

This is the same pattern as #185 (sentinel + init guard) at smaller scale: a structural commitment encoded so the bug becomes impossible-by-construction.

## Verdict
