# S2: partition match (PR #185)

## Input partition (cases the preferences force the design to distinguish)

- forEach absent / present on a node.
- forEach binding with valid single variable / invalid multi-variable / empty / non-string value.
- forEach written as flat-map YAML / array YAML.
- per-item `propagateWhen` gate present / absent.
- per-item gate first false at index k / never false during expansion.
- forEach item identity new / unchanged / removed since last reconcile.
- new `NodeState` value added by a future change / not added.
- `nodeStateLabels` in sync with exported `NodeState` constants / out of sync.

## Branching partition (cells design-pre distinguishes)

- forEach map nil vs non-nil.
- forEach YAML shape: flat-map branch vs array branch in `parseNodeList`.
- forEach map cardinality: 0 (rejected via empty check), 1 (accepted), >1 (rejected at a runtime guard *after* the map is built).
- forEach map iteration: `for varName, collectionExpr := range node.ForEach` in four call sites; loop shape admits multiple entries even though only one is reachable.
- `hasPerItemGate` computed twice (outer + inner-loop shadow) with the same operand.
- `nodeStateLabels` ↔ `NodeState` consistency: not branched on; commented as a maintenance obligation.
- `reconcileState.nodeCount`: set, never branched on.

## Branching partition (cells design-post distinguishes)

- forEach map nil vs non-nil (via `*ForEachBinding` nil check).
- forEach YAML shape: flat-map branch vs array branch in `parseNodeList`.
- forEach cardinality: 0 (rejected before binding constructed), 1 (accepted), >1 (rejected before binding constructed); each YAML branch validates inline.
- forEach binding access: direct field read of `VarName` and `Expr`; no iteration.
- `hasPerItemGate` computed once.
- `nodeStateLabels` ↔ `_nodeStateCount` consistency: branched on at `init()`; mismatch panics with diagnostic.

## Cells in pre's branching partition not in post's

- **forEach map cardinality > 1 reachable then rejected.** Classification: **(a) relocated to types**. `*ForEachBinding` cannot represent the case; the runtime guard is unreachable by construction.
- **forEach map iteration loop.** Classification: **(a) relocated to direct field access**. Four call sites collapse from `for varName, collectionExpr := range node.ForEach` to `node.ForEach.VarName` / `.Expr`.
- **Inner re-declaration of `hasPerItemGate`.** Classification: **(b) deleted**. The input case (computing the gate flag for this reconcile) is still handled by the outer declaration; the inner one branched on nothing.
- **`reconcileState.nodeCount` field.** Classification: **(b) deleted**. The input case (tracking node count for status derivation) was never an input case the preferences rewarded — no consumer existed.

## Cells in post's branching partition not in pre's

- **`init()` asserts `len(nodeStateLabels) == int(_nodeStateCount) - 1`.** Classification: **(a) preferences require this distinction**. Correctness rewards catching out-of-sync state at startup rather than at first metric emission. Pre-state's branching partition was coarser than the input partition required: "new `NodeState` added without label update" was an input case the design did not distinguish.

## Verdict

**S2 improved.** Pre's branching partition was finer than the input partition rewarded along three axes (cardinality reachability, map iteration over guaranteed singleton, redundant gate computation) and coarser along one axis (label/state sync was an unhandled input case). Post collapses the over-fine cells (relocation to types) and adds the missing cell (init-time assertion). The change is a partition-match move along all four axes the preferences touch.

Citation: three pre cells collapse via relocation/deletion; one post cell is added to cover an input case pre did not branch on.
