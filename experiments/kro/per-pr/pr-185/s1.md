# S1: deletion-minimality (PR #185)

## Procedures in design-pre absent from design-post

- **forEach normalization** (`parseForEachMap`). Classification: **(b) absorbed**. Cardinality validation, value-type check, and binding construction moved inline into `parseNodeList`'s map and array branches. The helper handled one job (extracting string values into a map) that the type-level rewrite obviated; the new branches build a `*ForEachBinding` directly without the intermediate map.

## Procedures in design-post absent from design-pre

- **Node state count assertion** (`init()` panic in `metrics.go`). Classification: **post (a)** — the preferences require this distinction. Pre-state left "is `nodeStateLabels` in sync with `NodeState`?" as a code-comment obligation. Post-state encodes it as a startup check that consumes the unexported `_nodeStateCount` sentinel.

## Properties in design-pre absent from design-post

- **P11** (pre: `reconcileState.nodeCount` field exists, set during walk, never read). Classification: **(a) deleted**. The input case "track node count for status derivation" was never serviced by any consumer; deletion loses no preference value.
- **P12** (pre: `hasPerItemGate` is computed at top of `reconcileForEach` and re-declared inside the outer iteration loop with the same operand). Classification: **(d) redundant**. The inner declaration shadowed the outer with identical value; deleting it changes no observable behavior.
- **P13** (pre: forEach iteration is over a map; the loop shape admits multiple entries by type). Classification: **(c) relocated to types**. The map-with-runtime-guard becomes `*ForEachBinding`; the single-dimension constraint is encoded at the Go type level rather than enforced after the fact.

## Properties in design-post absent from design-pre

- **P10** (post: `init()` asserts label/state count). Classification: **post (a)**. Preferences require correctness under future state additions; pre-state's code-comment obligation is not load-bearing.
- **P11** (post: `ForEach` is single-dimension by type). Classification: **post (a)**. Public API stability and correctness both reward making the constraint visible at the type signature; callers cannot construct multi-variable forEach.

## Verdict

**S1 improved.** The change is deletion-minimal in the strong sense: every removal falls into (a) servicing no input case, (c) relocation to a more constraining layer, or (d) self-redundancy. Two of the three additions are structural carries for distinctions the design previously left to comments. The fourth pre-state procedure (`parseForEachMap` helper) is absorbed cleanly. No introduced complexity that the preferences do not reward.

Citation: pre P11/P12/P13 → all three are (a)/(d)/(c) respectively; post P10/P11 are post-(a).
