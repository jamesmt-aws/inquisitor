# S2: partition match (design pair)

Inputs: `design-pre.md`, `design-post.md`, plus preferences preamble.

List the **input partition**: cases the stated preferences force the design to distinguish (e.g., child node ready vs not, watch event vs resync timer, forEach child added vs unchanged vs removed, hard dependency vs soft dependency, new exported state vs not, etc.).

List the **branching partition** for design-pre: cells implied by its named Procedures, conditions, dispatch points, and runtime guards.

List the **branching partition** for design-post: same.

For each cell in pre's branching partition **not in post's**, classify:

(a) collapsed because the distinction was relocated (cite where in post).
(b) collapsed because the distinction was deleted (state whether the input case still needs to be handled).

For each cell in post's branching partition **not in pre's**, classify:

(a) the preferences require this distinction (the input partition required it; pre missed it).
(b) the distinction is finer than the input partition rewards (introduced complexity).

**Verdict for S2.** Does the post-design's branching partition match the input partition more closely than pre's?
- `improved` if pre's over-fine cells are collapsed via (a) or (b)-with-no-loss, and any post (a) additions cover input cells pre missed.
- `regressed` if (b) deletions lose input cases the preferences require, or post (b) additions over-distinguish.
- `unchanged` if the partition shape is preserved.

Cite one line per classification.
